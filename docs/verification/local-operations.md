# 本地验证与微信一分钱流程

日期：2026-10-17。用户最新要求覆盖此前云端测试门槛：无需搭建独立测试环境，以本地测试推进当前功能。历史云端脚本保留为可选工具，不是本轮交付前置条件。

## 本地验证

`bash scripts/check.sh` 运行本机单元测试、静态检查、类型检查和前后台构建，不需要数据库、Redis、对象存储、SMTP 或云端账号。不用提供 SSH 或配置测试主机。

数据库事务、迁移及并发测试保留源码；没有执行时只标记未执行，不把它们作为继续改善后台的阻塞项。本轮不自动清理既有 Docker 容器或数据卷。

## 微信人工付款流程

当前功能是人工收款与核账，不是微信支付商户 API 对接。金额使用整数分；0.01 元对应 `price_cents=1`，不修改正式商品的原价。

1. 在后台新建专用于流程验证的商品，价格填写 `0.01`。教程准备并发布章节；数字商品先上传文件。确认上架后再下单。
2. 收款配置使用微信渠道，由运营人员自行填写真实收款人、收款账号及转账说明，核对配置后再交给测试者。不把真实账号、二维码、付款凭证或流水写入仓库。
3. 用普通用户账号购买测试商品，核对收银台是 `¥0.01`，向运营人员确认的微信收款人转账一分钱，上传凭证。
4. 运营人员进入待审核列表，在微信真实账单中核对收款人、金额、时间和交易流水；实际到账填写 `0.01`，选择微信收款，填写流水并勾选已核实，再批准。
5. 确认订单完成、对应教程或文件可访问；服务订单进入履约并生成工单。没有付款或凭证不符时驳回，并验证可重新提交。
6. 如验证退款，先由运营人员在微信实际退款，再登记同额退款与流水；核对该订单权益已撤销。系统不会自动转账。

自动单测与浏览器夹具仅验证软件流程，不会发送真实微信付款。实际一分钱转账和账单核对由操作者执行，本轮不得据单测声称已经真实到账。

## 后台操作体验（用户已确认并实施）

- `/admin/` 默认进入运营工作台；通过实际接口读取待审核付款、待履约订单、全部订单与商品数量，失败项显示不可用，不以零冒充成功。最近待审核记录可直接进入带订单号的审核队列。
- 导航按日常交易、商品与内容、运营记录分组；提供面包屑与查看商城入口，支持桌面和手机布局。
- 订单支持按历史订单号、买家邮箱、商品名称搜索，以及全部订单状态（含交付中）筛选、分页、重置；筛选记录在 URL 中。分页及总数使用一致的后端查询条件，仍按用户隔离。
- 列表丢弃迟到响应并取消旧请求；重试和审核后刷新沿用已提交的筛选，不偷偷应用尚未提交的输入。
- 商品按教程/数字商品/服务分别展示发布步骤；数字商品和服务不再显示创建教程入口。文件上传时禁止保存。分类读取失败可单独重试，已填写内容保留，恢复前禁止覆盖分类。
- 付款审核展示实际核账步骤；预选订单渠道，金额或渠道不一致时禁止批准并解释原因；批准仍要求操作者勾选已核实到账。已处理凭证以只读方式查看，操作进行中不可关闭弹窗。

## 本地验证入口

```sh
bash scripts/check.sh
npm run test:admin
```

第一条执行单元测试、格式/Clippy、类型检查与 Web/Admin 构建。第二条只启动本机 Vite 与浏览器，用 HTTP 接口夹具覆盖工作台、筛选、分类指引、失败状态和微信一分钱审核；不启动数据库、Redis、对象存储或邮件服务，不要求独立测试环境。

本机 macOS 使用已安装 Chrome；其他平台使用本机 Playwright Chromium。浏览器报告位于 `.runtime/admin-ui-report`，截图为 `.runtime/admin-workbench-desktop.png` 与 `.runtime/admin-workbench-mobile.png`，均是虚构夹具数据。
